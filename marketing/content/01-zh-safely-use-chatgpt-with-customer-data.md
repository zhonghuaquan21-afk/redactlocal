# 把客户数据喂给 ChatGPT 之前，我们先把这些信息抹掉了

> 面向知乎 / 公众号的中文改写版（不是直译）。英文原稿见
> [01-safely-use-chatgpt-with-customer-data.md](01-safely-use-chatgpt-with-customer-data.md)。

---

一个越来越常见的会议场面：

业务说，客服每天要处理 200 张工单，想用大模型做自动归类和回复草稿，能省两个人。
法务说，工单里有客户姓名、手机号、身份证号、订单和卡号后四位，这些不能出现在第三方系统里。

两边都对。结果是项目停在这里，一停就是半年。

大部分团队最后会在两个坏选项里选一个：要么彻底不用 AI（业务吃亏），要么偷偷用（法务不知道，出事一起完蛋）。其实还有第三条路，而且不需要采购、不需要改造系统，当天就能跑起来：

**先把敏感信息在本地抹掉，再交给 AI，拿到结果后再把真值换回去。**

这篇文章讲清楚具体怎么做、能覆盖什么、以及在哪一步会失败。

---

## 一、先想清楚：粘出去的到底是什么

大多数人对"我粘了一段工单给 AI"的风险感知是模糊的。拆开看，一次粘贴通常包含五类东西：

| 内容 | 为什么危险 |
|---|---|
| 姓名、手机号、邮箱 | 直接标识符，能直接指向一个人 |
| 身份证号 | 18 位，中间 8 位就是出生日期，等于暴露年龄和生日 |
| 卡号、订单号 | 金融数据；订单号还能和你的数据库关联回具体客户 |
| 自由文本备注 | 往往夹带健康、家庭、纠纷细节，当事人自己都没想到要外传 |
| 内网 IP、接口日志里的 Token | 这不是隐私问题，是安全事故 |

两件事让情况更糟：

1. **数据离开了你的边界。** 不管服务商的留存政策写得多好，你已经把一份拷贝交出去了。
2. **你收不回来。** 删对话不等于删日志、删备份、删风控流水。

《个人信息保护法》第 6 条讲"最小必要"，《GDPR》第 5 条讲 data minimisation——说的其实是同一件事：**能少给就少给。** 脱敏就是把这句话变成技术动作。

## 二、三种方案，老实对比

| 方案 | 成本 | 落地时间 | 真正的问题 |
|---|---|---|---|
| 干脆不用 AI | 0 | — | 效率落后，客户等回复 |
| 上企业级 DLP / 脱敏网关 | 几万到几十万/年 | 3–6 个月 | 采购走完，同事嫌慢不用 |
| **本地脱敏后再发** | 0 起 | 当天 | 部分信息会漏，需要人工扫一眼 |

第三种不是合规方案，它是一项**数据最小化措施**。但它是一个五人团队这周就会用上的唯一方案。

先把期望放正：它的价值不是"绝对安全"，而是"把每次都裸奔，变成大部分时候穿衣服"。

## 三、具体怎么做：五步

### 第 1 步：在文本离开你电脑之前处理掉

关键词是**本地**。判断标准很简单：处理时有没有网络请求。浏览器标签页里跑、或者是一个本地文件，都可以；在网页上点"上传文件"就不行。

替换方式建议用**结构化占位符**，不要用星号打码：

```
处理前：李娜（13812345678）反馈订单 A1002 一直没到。
处理后：[CN_NAME_1]（[PHONE_CN_1]）反馈订单 [ORDER_1] 一直没到。
```

占位符干两件事，星号干不了：**句子对模型来说还是通顺的**，而且**可逆**。

### 第 2 步：映射表留在本地

现在真正敏感的东西变成了这张表（占位符 → 真值）。三条规矩：

- 存本机，默认不要放共享盘
- 任务结束就删
- **千万别把映射表和脱敏文本一起粘进同一个对话**——那样等于没做

### 第 3 步：正常提问

模型对占位符的适应程度比大多数人预期的高。"请给 [CN_NAME_1] 写一封道歉信，说明 [ORDER_1] 延迟原因"，写出来的信里也会用 `[CN_NAME_1]`。模型本来也不需要知道客户叫什么，才能写出一封得体的道歉信。

### 第 4 步：发出去之前还原

用映射表把模型回答里的占位符换回真值。到这里你得到了一封 AI 写好、含真实客户信息的回复，而这份数据从没离开过你的电脑。

### 第 5 步：留痕，但别留数据

如果公司要审计，记录**"做过脱敏"这件事**（时间、工具、抹掉了哪几类），不要记录被抹掉的内容。审计要的是"有控制措施"的证据，不是 PII 的第二份拷贝。

## 四、哪些该抹，哪些别动

抹太多，提示词就没用了；抹太少，等于白做。一个能用的默认策略：

**必须抹**：邮箱、手机号、身份证、护照、银行卡、IBAN、API Key / Token / password、内网 IP

**看情况抹**：
- 姓名——除非语气/称呼性别对任务有影响
- 地址——如果任务只关心物流，保留城市就够
- 客户号/订单号——需要跨轮次追踪"同一个人"时，保留

**不用抹**：产品名、错误信息、堆栈（去掉密钥后）、日期、金额、以及客户真正在问的那个问题

一句话原则：**抹掉"能指认是谁"的，保留"描述问题"的。**

---

## 五、边界：会失败的地方（这段别删）

诚实地列出来，因为"以为自己安全了"比"知道有风险"危险得多。

- **散文里的自由姓名抓不住。** "我老公老张昨天打电话说锅炉坏了"——正则拿"老张"没办法。要靠名单、NER 模型，或者人工复核。
- **间接标识符。** 罕见职位 + 城市 + 日期，不带一个姓名也能定位到人。脱敏解决不了 k-匿名问题。
- **图片和附件。** 发票截图不在文本脱敏的射程内。
- **映射表本身。** 它现在是一张高浓度的 PII 清单，按密码文件的规格对待。
- **合规不靠工具。** 合法性基础、告知同意、留存期限、委托处理协议，是另外四个问题，得由法务判断。这个工具不构成法律意见。

## 六、怎么验证"真的不上传"

"本地运行"在成为卖点之前，先是一个可以被验证的事实。两分钟：

1. 打开页面，按 F12，切到「网络」，清空
2. 粘一段带手机号的文本
3. 看有没有请求发出、请求体里有没有你的文本
4. 更彻底的办法：断网再试，行为应该完全一样

如果它是一个单文件 HTML，`Ctrl+U` 能看到全部源码，搜 `fetch(`、`XMLHttpRequest`、`sendBeacon`，就能知道它**有没有能力**联网。

---

## 七、从哪一步开始落地

不要一上来改流程。建议这么推：

1. **先自己用一周。** 只在你最常粘贴的那个环节（比如客服工单）用，记录漏检的例子。
2. **写成一页 SOP。** 五步流程 + 三条禁忌（映射表不外传、别和原文一起粘、用完删）。SOP 比工具重要。
3. **再推给一个人。** 找最痛的那个同事，不找最闲的。
4. **最后才谈合规。** 拿着"我们做过数据最小化"的证据去找法务，比空口讲"我们会小心的"有用得多。

## 八、如果你不想自己搭

我把它做成了一个工具：[RedactLocal](/)——单个 13 KB 的 HTML 文件，双击打开、断网可用、全程不上传。

- 识别 12 类：邮箱、手机号（含 +86）、身份证、银行卡（Luhn 只作参考，打错一位也照样遮蔽）、IP、API Key、JWT、`password=` 键值对，以及带上下文的中文姓名和地址
- 替换方式四种：占位符 / 打码 / 哈希 / 直接删除
- 映射表可导出，还原面板一键换回真值
- 整张 CSV 可以批量处理，保留结构

免费版 5000 字符，够验证流程；专业版不限长度、支持批量文件和自定义规则。

工具解决的是"做不做得到"，SOP 解决的是"会不会一直做"。两个都得有。
